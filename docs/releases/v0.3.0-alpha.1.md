## Lightweight macOS preview

For **macOS 13 or later, Apple Silicon (arm64)**. Uses the system WKWebView, without bundling Electron, Node.js, .NET or another browser runtime. See the attached manifest for measured compressed/expanded sizes and SHA256SUMS.txt before installing.

### Features brought from the Windows receiver
- Connection and native-input diagnostics distinguish rejection from possible partial/unknown input.
- Pause, disconnect, revoke and reset cancel pending input. Already posted events cannot be recalled.
- Strict input is the default. Compatibility input is an explicit, warned, session-only choice that resets on reconnect.
- Optional phone Enter-after-text starts off and requires a supporting receiver. Enter can send a message or execute a command; it follows successful text submission and fresh safety checks.
- Separate, explicit Accessibility/event-posting controls and fail-closed Resume. Permissions are never granted automatically.
- Keychain-backed authenticated credential encryption, with no plaintext fallback.

### Existing Electron installation
This receiver uses a **separate profile**. Existing relay URLs and pairings are not migrated, overwritten or deleted. Enter the **same relay URL** already in use and explicitly pair the new receiver with SAS verification. Do not reset the old profile merely to install this preview. Windows releases are unchanged.

### Verification and remaining limits
Hosted CI passed native macOS Rust/Objective-C tests, actual bundled app/WKWebView startup, phone browser/loopback integration, and Windows regression tests/build/startup for the implementation.

On macOS 15.3.1 arm64, the candidate archive/manifest hashes and ad-hoc signature integrity were verified, and a normal launch process was observed. **Window interaction, actual text input, permission flows and Keychain persistence were not functionally tested** because UI testing access was not authorized. No retry or bypass was attempted. A local spctl assessment returned an internal Code Signing error and was inconclusive. This is a preview, not a stable or fully accepted release.

Missing, empty or AXUnknown subrole/password metadata is refused in both modes; some normal or custom editors may be unsupported. Submission does not prove that the target accepted or saved text. Uncertain input is never automatically resent.

### Manual acceptance checklist
With user-authorized access and dedicated harmless fields, verify:
- Startup, window/tray reopen and explicit permission grant/denial.
- Pair/SAS verification and saved identity across restart.
- Chinese, emoji, multiline and selection replacement.
- Strict/compatibility target checks and safe password/unknown-target refusal.
- Enter off/on, pause/disconnect/revoke during input, held modifiers and focus changes.

Do not use existing documents, production shells or destructive workflows for testing.

The app is **ad-hoc signed, not Developer ID signed or notarized**. Respect Gatekeeper and quarantine. No security-policy bypass, credential change, production relay deployment, domain change or automatic updater is included.
